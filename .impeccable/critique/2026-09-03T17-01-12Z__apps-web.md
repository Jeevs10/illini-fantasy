## Design-specificity verdict

The design *system* is specific; the product *design* is interchangeable. All
three mechanics that define this league exist as data and are absent as form:
per-game locks, the games cap, and archetype-derived slot eligibility.

Nothing about the interface is *college basketball*. No conference structure
past a grey sub-label, no sense of a Saturday slate versus a dead Tuesday, and
ten teams named "Team 1".."Team 10" with no logo, colour or manager name — in a
20-manager league where knowing who you are playing is the point.

## RESOLVED in 72e651d

## OPEN — backlog for the next polish

### P1

- **The games cap is stated, never drawn.** /league renders ~40 rows with 22
  dimmed. Show the nine counted, rule off after the ninth with the cap total,
  collapse the rest behind a disclosure. apps/web/app/league/page.tsx.
- **No help anywhere.** Zero glossary in a product built on a bespoke six-block
  model, a games cap and archetype eligibility. Three position vocabularies run
  in parallel with no mapping: role ("Scoring PG"), archetype ("lead"), slot
  ("G").
- **The player card omits the archetype weights** — the only part of the model
  that differs between a lead and a big, on the page that exists to explain the
  score. apps/web/app/players/[id]/page.tsx.
- **`opponentStrength` has no scale, unit or direction.** "strength 0.99" beside
  Arizona tells a new manager nothing.
- **error.tsx prints error.message raw** to a league manager.

### P2

- No sort on any of four tables; no archetype/slot filter in the pool.
- Pool ranks by Total, which buries better players with fewer games; no way to
  re-sort by Avg.
- Rejected lineup moves leave the uncontrolled select showing the invalid value
  while the notice sits above the table, off-screen.
- `disabled={busy}` is shared across all selects, so one change greys the table.
- Standings sorts by wins then PF and says so nowhere; team rows are not links.
- All loading.tsx files are byte-identical generic skeletons.
- Game log is unbounded — a 30-game player renders 180 bars with no summary.
- Block bars are 58-118px on desktop and ~650px on a phone; the diagnostic
  reads better on the small screen.

## Environment caveats for the next run

- `resize_window` is non-functional here: it reports success but innerWidth
  never changes and outerWidth is 0. Use a same-origin iframe for responsive
  work. An earlier in-session "checked at 420px" was actually 1458px.
- Synthetic CDP Tab keypresses do not move activeElement off BODY; use
  focus({focusVisible:true}) to exercise :focus-visible.
- The app needs ILLINI_TODAY / ILLINI_NOW set or every lineup reads as locked.
